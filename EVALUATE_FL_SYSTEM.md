### Federated Learning Evaluation – `evaluate_fl_system.py`

This document explains how to use `evaluate_fl_system.py` to evaluate trained federated learning (FL) models for both **classification** (packets) and **regression** (GPS/IMU) tasks.

---

### 1. Overview

`evaluate_fl_system.py` can:

- **Load checkpoints** from the server (and optionally clients)
- **Load test data** from prepared client CSVs or `test_data.npz`
- **Evaluate** classification or regression performance
- **Plot** metrics over rounds and client heterogeneity
- **Generate reports** (`JSON` + human‑readable text) into an output directory

Typical usage from the project root:

```bash
python evaluate_fl_system.py ^
  --checkpoint-dir checkpoints ^
  --data-dir data/train/packets ^
  --task classification ^
  --config config_classification
```

---

### 2. Required Inputs

- **`--checkpoint-dir`** (required)  
  Path to the directory containing server checkpoints, e.g. `checkpoints`.  
  - Files should be named like `server_round_XX.pt` (created by the training script).

- **`--data-dir`** (optional but recommended)  
  Directory with evaluation data:
  - For **packet classification**: CSVs such as `packet_client_000.csv`, `packet_client_001.csv`, … (typically generated by `prepare_fl_data_for_run_fl.py` into `data/train/packets`).
  - For **GPS/IMU regression**: CSVs like `gps_client_000.csv`, `imu_client_000.csv`, etc.

- **`--config`** (required, but has default)  
  Name of the Python config module defining the model and data settings:
  - Classification (packets): `config_classification`
  - Regression (GPS/IMU): `config_regression`
  - Generic: `config` or other custom configs

---

### 3. Key Command‑Line Arguments

From `main()` in `evaluate_fl_system.py`:

- **`--checkpoint-dir`**: Directory with `server_round_*.pt` (required).
- **`--data-dir`**: Directory with client data files (`packet_client_*.csv`, `gps_client_*.csv`, `imu_client_*.csv`).
- **`--task`**: `'classification'`, `'regression'`, or `'auto'` (default `'auto'`; auto‑detects from checkpoints/config).
- **`--test-split`**: Fraction of each client’s data reserved for test (default `0.2`).
- **`--output-dir`**: Output directory for reports and plots (default `evaluation_results`).
- **`--device`**: `'cuda'` or `'cpu'` (default: auto‑detect).
- **`--rounds`**: Specific rounds to evaluate (e.g. `--rounds 10 20 30`); default is **all** rounds.
- **`--config`**: Config module name (e.g. `config_classification`, `config_regression`).
- **`--evaluate-clients` / `--no-client-eval`**: Enable or disable per‑client model evaluation.

---

### 4. Typical Usage Patterns

#### 4.1. Packet Classification (using `config_classification`)

1. **Train** the FL system (from project root), for example:

```bash
python .\fl-classification\run_fl_system_classification.py ^
  --data-dir .\data\train\packets ^
  --config config_classification ^
  --learning-mode classification
```

2. **Evaluate** the trained model:

```bash
python evaluate_fl_system.py ^
  --checkpoint-dir checkpoints ^
  --data-dir data/train/packets ^
  --task classification ^
  --config config_classification
```

This will:

- Load all `server_round_*.pt` checkpoints.
- Use `packet_client_*.csv` files from `data/train/packets` as client‑level datasets.
- Build sliding windows using `WINDOW_SIZE` and `OVERLAP` from `config_classification`.
- Evaluate classification metrics (accuracy, precision, recall, F1, ROC‑AUC).
- Generate plots and reports into `evaluation_results/`.

#### 4.2. GPS/IMU Regression (using `config_regression`)

```bash
python evaluate_fl_system.py ^
  --checkpoint-dir checkpoints ^
  --data-dir data/train/gps-imu ^
  --task regression ^
  --config config_regression
```

This will:

- Prefer `gps_client_*.csv` / `imu_client_*.csv` in `data/train/gps-imu`.
- Build time‑series windows.
- Evaluate regression metrics (RMSE, MAE, R²).

---

### 5. Outputs

For a given `--output-dir` (default `evaluation_results/`), the script produces:

- **`evaluation_report.json`**: Machine‑readable summary of:
  - Task type, checkpoint/data directories
  - Per‑round metrics per test set
  - Optional client‑specific results and heterogeneity statistics

- **`evaluation_report.txt`**: Human‑readable text report including:
  - Best and final performance per test set
  - Per‑round server and client‑specific metrics
  - Client heterogeneity statistics (if client evaluation is enabled)

- **Plots** (PNG files), for example:
  - `classification_metrics_<test_name>.png` or `regression_metrics_<test_name>.png`
  - `client_heterogeneity_classification.png` / `client_heterogeneity_regression.png`
  - `client_performance_distribution.png`
  - `confusion_matrices_<test_name>.png` (classification)
  - `predictions_vs_actual_<test_name>.png` (regression)

---

### 6. Notes & Tips

- **Import paths**: `evaluate_fl_system.py` automatically adds `fl-classification/` to `sys.path` so it can import `DataPreprocessorClassification`.
- **Data format**: For classification, ensure:
  - Packet CSVs contain the features listed in `config_classification.PACKET_FEATURES`.
  - Label column matches `config_classification.LABEL_COL`.
- **Client alignment**: If you used the updated `prepare_fl_data_for_run_fl.py`, each client has the same number of packet windows, which keeps training and evaluation rounds aligned across clients.

For more details, see the docstrings and comments inside `evaluate_fl_system.py`.
